やってはいけないWebアニメーション 8選
── UXを壊すモーションの共通点

2026年3月3日　／　著者：rei　／　読了時間：約10分

Advertisement

「アニメーションをつければUXが上がる」という誤解があります。残念ながら、実際のWebサイトには「良かれと思ってつけたアニメーションがUXを損なっている」ケースが溢れています。この記事では典型的な8つのアンチパターンを、理由と改善策と共に解説します。

❌ NG1：ページ全体の入場アニメーションが長すぎる

問題：ページ読み込み時に2秒以上の「オープニング演出」があるサイト。コンテンツが見えるまでの時間が長く、ユーザーは「フリーズした？」と感じます。

改善：ヒーロー要素の入場アニメーションは最大600ms以内、スタッガーを使う場合も全体が完了するまで1秒以内に設計する。

// ❌ 2500msの入場アニメーション
anime({ targets: '.hero', opacity: [0, 1], duration: 2500 });

// ✅ 500ms以内、スタッガーで差別化
anime({ targets: '.hero > *', opacity: [0, 1], translateY: [16, 0], delay: anime.stagger(80), duration: 400 });

❌ NG2：スクロールを妨げるパラレックス

問題：スクロールに対してページのスクロール位置とは異なる速度でコンテンツが動くパラレックス効果。モーション酔いの主要原因であり、スクロール性能も低下します。

改善：背景のみへの適用に限定し、移動量は最大20px程度にする。prefers-reduced-motion時は必ず停止。

❌ NG3：ループし続ける無関係なアニメーション

問題：ページ辺縁で意味もなくループする浮遊するアイコン・回転するオーナメントなど。ユーザーの注意を本来のコンテンツから奪います。

改善：ループアニメーションを使うのはローディングスピナー・プログレスバーなど「進行中」を示す場面のみ。

❌ NG4：クリックに反応しないボタン（アニメーション中のインタラクション無視）

問題：アニメーション実行中にbuttonをpointer-events: noneやdisabledにし続け、ユーザーが複数回クリックしても反応しない。

改善：アニメーション中でも「2回目のクリックはアニメーションを即座に完了させてアクションを実行」するか、アニメーション時間を短くして待機感を解消する。

// アニメーション中の多重クリックを適切に処理
let isAnimating = false;
btn.addEventListener('click', () => {
  if (isAnimating) {
    anime.remove(btn); // アニメーション即座に中断
    executeAction();
    return;
  }
  isAnimating = true;
  anime({ targets: btn, scale: [1, 0.95, 1], duration: 200, complete: () => { isAnimating = false; }});
  executeAction();
});

❌ NG5：duration 1000ms以上の日常操作

問題：ドロップダウンの展開が1秒かかる、モーダルが2秒かけて出現するなど。操作を「待たされる」感覚はスマートフォンのネイティブアプリ体験と比較され、大きなUX低下になります。

改善：日常的なUIアクション（開く・閉じる・切り替え）は最大400ms。300ms以下が理想。

❌ NG6：easeInで始まるUIアニメーション（遅い出だし）

問題：easeInは最初がゆっくりで徐々に加速するイージング。コンテンツの出現に使うと「重くてもたついている」印象を与えます。

改善：登場（enter）アニメーションはeaseOut（速いスタート・ゆっくり着地）が基本。easeInは退場（leave）アニメーションに使う。 

// ✅ 登場: easeOut、退場: easeIn
function enter(el) { anime({ targets: el, opacity: [0, 1], translateY: [16, 0], easing: 'easeOutCubic' }); }
function leave(el) { anime({ targets: el, opacity: [1, 0], translateY: [0, -8], easing: 'easeInCubic' }); }

❌ NG7：reduced-motion 非対応のサイト

問題：prefers-reduced-motionを全く考慮せず、前庭機能障害を持つユーザーに激しいアニメーションを強制する。これはアクセシビリティ上の重大な問題で、一部の国では法的問題になりうるほどです。

改善：必ずprefers-reduced-motion対応を実装する。モーション配慮設計ガイドを参照。

❌ NG8：CLS（累積レイアウトシフト）を引き起こすアニメーション

問題：アニメーション開始時または完了時に、周囲のコンテンツが突然ズレる現象。Core Web Vitalsの「CLS」スコアが悪化し、SEOにも影響します。

改善：アニメーション前から要素の最終サイズ（width/height）を確保しておく。translateを使って位置をずらし、position: absoluteで他の要素への影響を切り離す。 

// ❌ height変化でCLS発生
anime({ targets: '#box', height: [0, 200] }); // 周囲がズレる

// ✅ translate + overflow: hiddenでCLS防止
// 事前にheight: 200pxを確保しておいてtranslateYでスライド表示
#box { height: 200px; overflow: hidden; }
anime({ targets: '#box-inner', translateY: ['-100%', '0%'] });

まとめ

悪いアニメーションの共通点は「ユーザーのためではなく、デザイナー・開発者の自己満足のために動いている」ことです。アニメーションを追加する前に必ず「これはユーザーの理解・操作を助けるか？」を問い直してください。
