パフォーマンスを犠牲にしないモーション設計

なぜパフォーマンスが重要か

美しいアニメーションを実装しても、60fps（フレーム毎秒）を下回るとユーザーは「カクつき（jank）」として認識し、むしろUXを損ないます。特にモバイルデバイスではCPU・GPU性能が限られるため、パフォーマンスへの意識は欠かせません。Google の Core Web Vitals でも「INP（Interaction to Next Paint）」という指標でスムーズな応答が評価されます。

ブラウザレンダリングパイプラインを理解する

CSSプロパティを変更すると、以下のパイプラインが再実行されます：

  • Style → Layout → Paint → Composite（レイアウト変更、最重）
  • Style → Paint → Composite（色・影変更、中間）
  • Style → Composite（transform・opacity、最軽・GPUのみ）

アニメーションは必ず最後の「Compositeのみ」になるプロパティを使いましょう。transform（translateX/Y, scale, rotate）とopacityのみです。

// ❌ left/topを動かす → Layout再計算（毎フレーム重い）
anime({ targets: '#el', left: 100 });

// ✅ translateXを使う → GPUで処理、Compositeのみ
anime({ targets: '#el', translateX: 100 });

DevToolsでフレームレートを計測する

Chrome DevTools → Performance パネル → アニメーション中に録画 → Frames セクションで各フレームの処理時間を確認できます。16.7ms（60fps）を超えているフレームがあれば改善対象です。

レイヤーパネル（Layers）で、アニメーション要素が個別のCompositeレイヤーに分離されているかも確認できます。

Intersection Observer でオフスクリーンを省略

// 画面内に入ったときだけアニメーションを実行（画面外は省略）
const io = new IntersectionObserver(entries => {
  entries.forEach(entry => {
    if (!entry.isIntersecting) return;
    anime({ targets: entry.target, opacity: [0, 1], translateY: [20, 0], duration: 500 });
    io.unobserve(entry.target); // 一度だけ実行
  });
}, { threshold: 0.15 });

document.querySelectorAll('.animate-on-scroll').forEach(el => io.observe(el));

will-changeの正しい使い方

// ✅ アニメーション開始直前に設定、完了後に解除
function animateCard(el) {
  el.style.willChange = 'transform, opacity';
  anime({
    targets: el,
    translateY: [30, 0],
    opacity: [0, 1],
    duration: 600,
    complete: () => { el.style.willChange = 'auto'; }
  });
}

// ❌ すべての要素に設定するのはNG（メモリ大量消費）
// .card { will-change: transform; }  ← CSSに書き散らすのは避ける

デバイス性能を考慮した動的制御

// 低性能デバイスではアニメーションを簡略化
const isLowEnd = navigator.hardwareConcurrency <= 2 || navigator.deviceMemory <= 2;
const duration = isLowEnd ? 200 : 600;
const staggerDelay = isLowEnd ? 0 : 80;

anime({
  targets: '.card',
  opacity: [0, 1],
  translateY: isLowEnd ? 0 : [20, 0],
  delay: anime.stagger(staggerDelay),
  duration
});

チェックリスト

  • ✅ translateX/Y, scale, rotate, opacity のみをアニメーション
  • ✅ width/height/top/left のアニメーションを避ける
  • ✅ will-change を適切に設定・解除する
  • ✅ Intersection Observer で画面外の省略
  • ✅ ループアニメーションをバックグラウンド時停止
  • ✅ DevTools Performanceでフレームレートを計測
  • ✅ prefers-reduced-motion 対応
