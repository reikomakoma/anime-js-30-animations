UIモーション設計の原則
── なぜアニメーションはユーザーを助けるのか

2026年3月3日　／　著者：rei　／　読了時間：約10分

Advertisement

アニメーションの本質：「伝えるための動き」

Webサイトやアプリにアニメーションを追加するとき、多くの開発者は「かっこよく見せたい」という動機で実装します。しかし、本当に優れたUIアニメーションの目的は「かっこよさ」ではありません。ユーザーが今何が起こっているのかを理解する手助けをすることです。

Googleの「Material Design」ガイドラインは、UIモーションに12の原則を定めています。その根底にある思想は「現実世界の物理法則に沿った動きは、人間の脳が最も自然に受け入れられる」というものです。このページでは、特に重要な5つの原則をanime.jsの実装例と共に深掘りします。

原則1：Informative（情報を伝える）

アニメーションの最重要の役割は「何かが変わった」をユーザーに伝えることです。例えば、ファイルをゴミ箱にドラッグすると「縮小しながらゴミ箱に消える」アニメーションがつきます。これにより「削除が完了した」という状態変化を、言葉を使わずに視覚的に伝えられます。 

// ファイル削除の演出（縮小してフェードアウト）
anime({
  targets: '#file-item',
  scale: [1, 0],
  opacity: [1, 0],
  translateY: [0, -10],
  easing: 'easeInCubic',
  duration: 300,
  complete: () => document.querySelector('#file-item').remove()
});

原則2：Focused（焦点を当てる）

画面上のすべての要素が同時に動くと、ユーザーはどこを見ればいいかわからなくなります。アニメーションは「今、ここを見て」という視線誘導ツールとして使う必要があります。一度に動かす要素は最小限に。

Stagger（遅延表示）はこの原則の完璧な実装例です。リストが上から順番に出現することで、ユーザーの視線は自然に上から下へ流れ、各要素を認識しやすくなります。

原則3：Expressive（感情を伝える）

「いいね！」ボタンを押したとき、ただ色が変わるだけより、ハートがピョンと跳ねる方がユーザーの感情に響きます。easeOutElasticによるバウンスは「システムが喜んでいる」という擬人的な印象を与え、ポジティブな感情的フィードバックを返せます。

重要：感情的なアニメーションは「感情が伴うアクション」にのみ使うこと。フォームのバリデーションエラーにElasticイージングをつけることは、場の雰囲気を読めていないUI設計です。

原則4：Efficient（効率的）

ユーザーはアニメーションを楽しむために来ているのではありません。タスクを完了させに来ています。日常的なUIアクション（ボタン押下・メニュー開閉等）のアニメーションは、200ms〜400msが適正です。それ以上は「待たされている」と感じさせます。

原則5：Consistent（一貫性がある）

同じ種類のアクションには同じアニメーションを使いましょう。サイト内で「出現はfadeIn+slideUp、消滅はfadeOut」というルールを一貫して適用すると、ユーザーはアニメーションのパターンを学習し、UIが直感的に感じられます。

anime.jsでこれを実現するには、共通のアニメーション関数を定義して全ページで再利用する設計が効果的です。

// 共通アニメーション関数の例
const UI = {
  enter: (el) => anime({ targets: el, opacity: [0, 1], translateY: [16, 0], duration: 380, easing: 'easeOutCubic' }),
  leave: (el, cb) => anime({ targets: el, opacity: [1, 0], translateY: [0, -8], duration: 220, easing: 'easeInCubic', complete: cb }),
  bounce: (el) => anime({ targets: el, scale: [1, 0.85, 1.2, 1], duration: 600, easing: 'easeOutElastic(1, 0.4)' })
};

まとめ：「なぜ動かすか」を最初に考える

アニメーションを実装する前に、毎回この問いを自分に課してください。「このアニメーションはユーザーの理解・操作・感情にどう貢献するのか？」

答えが出ない場合、そのアニメーションはおそらく不要です。目的のあるモーションだけがUIを豊かにします。
