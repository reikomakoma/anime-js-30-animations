ミス1：ターゲットが存在しない状態でアニメーションを呼ぶ

最もよくある原因。targetsに指定したCSSセレクタに一致する要素がDOMに存在しない場合、アニメーションは静かに失敗します（エラーが出ない）。

// ❌ DOM読み込み前に実行している
anime({ targets: '#modal', opacity: [0, 1] }); // nullになる

// ✅ DOMContentLoaded後（またはscriptタグをbody末尾）
document.addEventListener('DOMContentLoaded', () => {
  anime({ targets: '#modal', opacity: [0, 1] });
});

// デバッグ：ターゲットを確認
console.log(document.querySelector('#modal')); // nullでないか確認

ミス2：プロパティ名のケース間違い

anime.jsではCSSプロパティ名をcamelCaseで指定します。ハイフン区切りのCSSプロパティ名はそのまま使えません。

// ❌ CSSのままのハイフン区切りは無効
anime({ targets: '#el', 'border-radius': '50%' });

// ✅ camelCaseで指定
anime({ targets: '#el', borderRadius: '50%' });

// SVGの場合は文字列のまま（一部例外あり）
anime({ targets: 'path', 'stroke-dashoffset': [100, 0] }); // これは動作する

ミス3：ループアニメーションのメモリリーク

loop: true のアニメーションは、対象の要素が削除されてもアニメーションオブジェクトが実行され続けます。コンポーネントのアンマウント時やSPA のルート変更時に必ず停止処理を入れましょう。

// アニメーションオブジェクトを変数で保持
const loopAnim = anime({ targets: '.loader', rotate: '1turn', loop: true, easing: 'linear' });

// 不要になったタイミングで停止
function cleanup() {
  loopAnim.pause();
  // または
  anime.remove('.loader'); // ターゲット指定で一括削除
}

// Reactの例
useEffect(() => {
  const anim = anime({ targets: ref.current, ... });
  return () => anim.pause(); // クリーンアップ
}, []);

ミス4：イベントハンドラの重複登録

クリックイベントでアニメーションを起動する場合、ハンドラを複数回登録するとアニメーションが重複して予期しない動作になります。

// ❌ クリックするたびにハンドラが増える
function setupButton() {
  document.querySelector('#btn').addEventListener('click', () => {
    anime({ targets: '#btn', scale: [1, 1.1, 1] });
  });
}
setupButton(); // 複数回呼ばれると重複登録される

// ✅ フラグで管理 または AbortController を使う
const btn = document.querySelector('#btn');
if (!btn._bound) {
  btn._bound = true;
  btn.addEventListener('click', () => {
    anime({ targets: btn, scale: [1, 1.1, 1] });
  });
}

ミス5：transformOriginの設定忘れ

scaleやrotateは変形の基準点（transform-origin）がデフォルトで「要素の中心」です。スケールアニメーションで「角から広がる」「上端を軸に回転」したい場合は事前にCSSでtransform-originを設定する必要があります。 

/* CSS */
#dropdown { transform-origin: top center; }

/* JavaScript */
anime({ targets: '#dropdown', scaleY: [0, 1], opacity: [0, 1], easing: 'easeOutBack' });

ミス6：durationが長すぎる

開発時に「ゆっくり動いてほしい」と感じて1000ms以上を設定しがちですが、日常的なUIインタラクションでは150〜400msが適正です。詳しくはタイミングとイージングガイドを参照。

ミス7：アニメーション値の型ミス

アニメーション値の指定は数値（px単位は省略）またはCSS値の文字列です。

// ❌ 数値に単位をつけると無効（translateは単位不要）
anime({ targets: '#el', translateX: '100px' }); // 動くが非推奨

// ✅ 数値のみ（anime.jsがpxと解釈）
anime({ targets: '#el', translateX: 100 });

// ✅ 文字列が必要なケース（%など）
anime({ targets: '#bar', width: ['0%', '80%'] });

// ✅ 回転
anime({ targets: '#icon', rotate: '1turn' }); // または 360 （deg）

ミス8：SVGモーフィングでポイント数が不一致

SVGのd属性をアニメーションする場合、変形前後のd属性のアンカーポイント数が完全に一致している必要があります。不一致の場合はモーフィングが正常に機能しません。 

// ❌ ポイント数が違う（M L L L Z = 4点 vs M L L L L Z = 5点）
anime({ targets: 'path', d: [{ value: 'M0,0 L100,0 L100,100 L0,100 Z' }] });
// 元のdが 'M0,0 L50,0 L100,50 L50,100 L0,50 Z' (5点) の場合は失敗

// ✅ ポイント数を揃える（両方5点に統一）

ミス9：staggerを使わずにdelayを手動計算

複数要素に個別にdelayを設定するのは保守性が低下します。anime.stagger()を使いましょう。

// ❌ 手動で計算（保守性が低い）
anime({ targets: els[0], opacity: [0,1], delay: 0 });
anime({ targets: els[1], opacity: [0,1], delay: 100 });
anime({ targets: els[2], opacity: [0,1], delay: 200 });

// ✅ staggerで自動計算
anime({ targets: '.item', opacity: [0, 1], delay: anime.stagger(100) });

ミス10：complete後に要素を操作しない

アニメーション完了後にdisplay:noneにしたい等の後処理は必ずcompleteコールバックで行います。

// ❌ アニメーション中にdisplay:noneを設定すると即消える
anime({ targets: '#el', opacity: [1, 0] });
document.querySelector('#el').style.display = 'none'; // アニメ中に消える！

// ✅ completeコールバックで後処理
anime({
  targets: '#el',
  opacity: [1, 0],
  duration: 300,
  complete: () => {
    document.querySelector('#el').style.display = 'none';
  }
});
